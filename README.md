# TripSketch AI

> 키워드로 여행을 계획하고, 상황이 바뀌어도 여행 목적을 유지하는 맞춤형 여행 플래너

이 문서는 프로젝트의 개발 계획을 정리한 README입니다. 아래 기능은 구현 목표이며, 실제 구현이 완료되었다는 의미는 아닙니다.

## 1. 프로젝트 개요

TripSketch AI는 사용자가 원하는 여행을 키워드나 짧은 문장으로 입력하면, 생성형 AI를 활용해 취향과 조건에 맞는 여행 일정을 제안하는 서비스입니다.

여행을 준비할 때는 관광지, 숙소, 이동 경로, 날씨, 준비물을 각각 검색해야 합니다. 검색한 정보를 날짜별로 정리하고 이동시간까지 고려하는 과정에는 많은 시간이 필요합니다. 특히 여행 계획이 익숙하지 않은 사람은 하고 싶은 활동이 있어도 어떤 장소를 선택하고 어떤 순서로 방문해야 할지 결정하기 어렵습니다.

이 프로젝트는 이러한 불편을 줄이기 위해 기획했습니다. 예를 들어 “부산 2박 3일, 바다 보면서 사진 찍고 쉬고 싶어. 차는 없어.”라고 입력하면, AI가 바다 감상·사진 촬영·휴식이라는 여행 목적과 대중교통 이용 조건을 정리합니다. 날짜와 예산처럼 필요한 정보는 추가로 확인한 뒤 날짜별 일정을 제안하도록 개발할 예정입니다.

일정을 처음 만드는 것뿐 아니라 여행 준비와 여행 중의 변경도 지원합니다. 비가 오거나 사용자의 컨디션이 달라지면 일정의 일부를 수정할 수 있습니다. 이때 이미 예약한 숙소와 식당은 유지하고, 사용자가 원했던 경험을 최대한 살리는 대안을 제시합니다. 해변 산책이 어려운 경우 바다를 볼 수 있는 실내 공간을 제안하고, 산책 경험은 줄어든다는 점도 함께 설명하는 방식입니다.

또한 같은 숙소를 매일 반복 입력하는 번거로움을 줄이고, 변경 전후 일정을 비교한 뒤 사용자가 직접 적용 여부를 결정할 수 있도록 합니다. 관광지 설명과 준비물 체크리스트도 일정에 연결하여, 여행 계획부터 실제 여행까지 한곳에서 확인할 수 있는 서비스를 만드는 것이 목표입니다.

초기에는 국내 한 도시의 1~3일 여행을 대상으로 개발합니다. 기본적인 일정 생성과 수정 기능을 먼저 완성한 뒤 지원 지역과 기능을 확대할 계획입니다.

## 2. 개발 목적

- 여행 정보를 따로 검색하고 정리하는 시간을 줄입니다.
- 간단한 입력으로 취향과 예산에 맞는 여행 계획을 시작할 수 있게 합니다.
- 날씨나 상황이 바뀌어도 원래의 여행 목적을 고려한 대안을 제공합니다.
- 확정된 날짜와 예약을 유지하면서 필요한 부분만 수정할 수 있게 합니다.
- 여행 일정과 준비물을 한곳에서 확인할 수 있도록 합니다.

## 3. 예상 사용자

| 사용자 | 필요한 도움 |
| --- | --- |
| 여행 계획에 익숙하지 않은 사람 | 장소 선택과 날짜별 일정 구성 |
| 준비 시간이 부족한 대학생·직장인 | 빠른 일정 작성과 여행 정보 정리 |
| 친구·커플·가족 여행객 | 취향과 상황을 고려한 일정 조정 |
| 숙소나 식당을 미리 예약한 여행객 | 예약을 유지하는 동선 구성 |

## 4. 주요 기능

| 기능 | 설명 |
| --- | --- |
| 키워드 기반 여행 분석 | 입력한 문장에서 여행 목적, 기간, 예산, 교통수단 등을 정리합니다. |
| 여행 의도 확인 | AI가 이해한 조건을 카드로 보여 주고 사용자가 수정할 수 있게 합니다. |
| 맞춤 일정 생성 | 관광·식사·휴식을 날짜별로 배치하고 이동 및 예약 조건을 확인합니다. |
| 관광지·숙소 정보 제공 | 여행 목적과 동선에 맞는 후보 및 추천 이유를 보여 줍니다. |
| 숙소 자동 배치 | 숙소와 숙박 기간을 한 번 등록하면 날짜별 출발·복귀 일정에 반영합니다. |
| 상황별 일정 수정 | 우천이나 컨디션 변화에 따라 선택한 날짜 또는 시간대만 수정합니다. |
| 변경 비교·복원 | 수정 전후 차이를 확인하고 적용하거나 이전 일정으로 되돌립니다. |
| 준비물 체크리스트 | 일정과 날씨에 맞는 준비물을 제안하고 체크 상태를 유지합니다. |
| 오늘·다음 일정 | 여행 중 다음 장소와 남은 일정을 쉽게 확인하도록 합니다. |

가격, 운영시간, 이동시간 등 확인되지 않은 정보는 추정값 또는 확인 필요 항목으로 표시합니다. 숙소의 실제 예약과 결제는 초기 개발 범위에 포함하지 않습니다.

## 5. 간단한 사용 예시

1. 사용자가 “부산 2박 3일, 바다·사진·휴식, 차 없음”을 입력합니다.
2. AI가 여행 목적과 조건을 정리하고, 사용자가 날짜·예산·예약한 숙소를 확인합니다.
3. 입력한 조건에 맞는 날짜별 여행 일정을 제안합니다.
4. 둘째 날 비가 오는 경우 사용자가 “오후만 실내 일정으로 바꿔줘”라고 요청합니다.
5. 기존 예약을 유지한 대체안과 변경 이유를 보여 줍니다.
6. 사용자가 변경안을 적용하면 일정과 준비물이 함께 갱신됩니다.

위 예시는 기능 설명을 위한 가상 상황입니다.

## 6. 시스템 구조

사용자 화면, 서버, AI 및 외부 데이터, 데이터베이스로 구성할 계획입니다.

| 구성 요소 | 역할 |
| --- | --- |
| 사용자 화면 | 여행 조건 입력, 일정 조회·수정, 준비물 확인 |
| 서버 | 사용자 요청 처리, 일정의 날짜·예약 조건 확인 |
| 생성형 AI | 여행 의도 분석, 일정·대체안 제안, 추천 이유 작성 |
| 외부 데이터 | 관광지·장소·날씨 등 여행 정보 제공 |
| 데이터베이스 | 여행 조건, 예약, 일정과 변경 이력, 준비물 저장 |

사용자가 조건을 입력하면 서버가 AI와 외부 정보를 활용해 일정 초안을 만듭니다. 서버에서 조건을 확인한 후 화면에 보여 주고, 사용자가 선택한 일정을 저장합니다.

구체적인 개발 언어와 프레임워크는 팀의 경험과 수업 환경에 맞춰 확정할 예정입니다.

## 7. UI/UX 구상

복잡한 메뉴를 줄이고, 입력부터 일정 확인까지 쉽게 이동할 수 있도록 구성합니다.

| 화면 | 주요 내용 |
| --- | --- |
| 여행 입력 화면 | 키워드·여행 날짜·예산·교통수단 입력, 여행 의도 확인 |
| 일정 화면 | 날짜별 일정 카드, 관광지 설명, 숙소와 고정 예약 표시 |
| 변경 비교 화면 | 변경 전후 일정과 이유 확인, 적용·취소·복원 버튼 |
| 오늘 일정·준비물 화면 | 다음 활동과 남은 일정, 준비물 체크박스 |

**간단한 화면 예시**

- 입력 화면: “어떤 여행을 원하시나요?” 입력창과 “일정 만들기” 버튼
- 일정 화면: “1일차 / 2일차 / 3일차” 탭과 시간순 일정 카드
- 변경 화면: “해변 산책 → 실내 공간 방문” 비교와 “변경 적용” 버튼
- 준비물 화면: 우산, 보조배터리 등 필요한 물품을 체크하는 목록

모바일에서도 보기 쉽도록 카드 중심으로 구성합니다. 예약된 일정에는 “고정” 표시를 붙이고, 일정을 수정하기 전 변경 내용을 먼저 보여 줍니다. 조회나 생성에 실패하면 재시도 안내를 제공하고 기존 일정은 유지하도록 합니다.

## 8. AI 활용방안

AI는 사용자의 문장을 이해하고 여행에 맞는 제안을 만드는 데 활용합니다.

- **의도 분석:** “차 없음”, “사진 찍기”, “조용한 여행” 등을 여행 조건으로 정리합니다.
- **일정 생성:** 확보한 관광지 정보를 바탕으로 날짜별 활동을 제안합니다.
- **대체안 제안:** 비가 오거나 일정이 지연되면 원래 목적에 맞는 대안을 제시합니다.
- **설명과 준비물:** 추천 이유와 활동에 필요한 준비물을 정리합니다.

시간·비용 계산, 예약 충돌 확인, 저장과 복원은 서버가 담당합니다. AI가 제안한 내용도 조건에 맞는지 확인하며, 정보가 부족하면 임의로 확정하지 않고 사용자에게 확인을 요청합니다. 사용할 AI 모델은 비용과 응답 품질을 비교하여 선정할 예정입니다.

## 9. 개발 일정

기존 계획에 따라 총 6주로 진행합니다. 실제 시작일과 발표일은 수업 일정에 맞춰 확정합니다.

| 기간 | 주요 작업 | 결과물 |
| --- | --- | --- |
| 1주차 | 요구사항 정리, 핵심 기능 선정, 간단한 화면·데이터 설계 | 기획서, 화면 구성안 |
| 2주차 | 여행 입력, 의도 분석, 일정 생성·저장 구현 | 기본 일정 생성 시제품 |
| 3주차 | 관광지·숙소·날씨 정보와 준비물 연결 | 여행 정보 연동 화면 |
| 4주차 | 부분 수정, 변경 비교·복원, 오늘 일정 기능 연결 | 통합 시제품 |
| 5주차 | 예약 유지, 저장·복원, 오류 처리 및 사용성 점검 | 최종 시연 버전 |
| 6주차 | README와 보고서 정리, 시연 영상 제작, 발표 준비 | 최종 제출 자료 |

4주차 말까지 주요 기능을 연결하고, 5주차 말에 시연 버전을 확정합니다. 6주차에는 새 기능 추가보다 오류 수정과 발표 준비에 집중합니다.

## 10. 기대 효과 및 향후 계획

사용자는 여행 계획에 드는 검색과 정리 시간을 줄이고, 자신의 취향이 반영된 일정을 쉽게 확인할 수 있습니다. 여행 중 상황이 바뀌어도 전체 계획을 다시 작성하지 않고 필요한 부분만 조정할 수 있을 것으로 기대합니다.

초기 버전이 완성되면 사용자 의견을 받아 화면과 추천 결과를 개선할 예정입니다. 이후 여러 도시 지원과 예약 이미지에서 정보를 읽어 오는 기능 등을 검토합니다. 실제 효과는 사용성 테스트를 통해 확인합니다.
